# LPF-регламент: Журнал гипотез

> Источник: пост [«Заметка это не столько про память, сколько про обратную связь»](https://systemsworld.club/t/zametka-eto-ne-stolko-pro-pamyat-a-skolko-pro-obratnuyu-svyaz/40105). Категория «Гипотеза» в классификации заметок → `note-review.md` шаг 3. Журнал → `{{GOVERNANCE_REPO}}/current/hypotheses-log.md`. Сверка вручную → `/verify-hypotheses`; в ритме недели → `week-close` шаг 6a.

## Триггер захвата

Не «не забыть бы записать», а: «какую гипотезу о мире я сейчас считаю истинной, и что могло бы её опровергнуть?» Нет ответа на вторую часть → это памятка/мысль-черновик (категория «Задача» или «Черновик»), не гипотеза.

## Четыре обязательных поля

| Поле | Правило |
|------|---------|
| **Утверждение** | Проверяемое предсказание, не эмоция и не намерение |
| **Уверенность** | Число в процентах на момент записи, не задним числом |
| **Критерий фальсификации** | Что конкретно посчитает гипотезу неверной; если утверждение количественное — явная базовая линия (иначе сверка неоднозначна) |
| **Дата сверки** | Конкретная дата («в пятницу», «через две недели», «1 сентября»), не «когда-нибудь» |

Без всех четырёх полей запись не гипотеза, а дневник — не пишется в журнал.

## Порог действия по уверенности

- **≥95%** → иду дальше, дополнительные проверки не добавляю
- **~80% при дорогой ошибке** → добавить проверку сейчас, не откладывать
- **~50%** → не принимать решение до дополнительных данных

Число не для красоты — оно определяет, что делать сейчас, до сверки.

## Заполнение — не при захвате

4 поля пишутся НЕ пилотом в момент мимолётной заметки (это разрушило бы low-friction capture). Note-Review распознаёт формулировку-предсказание, пишет черновик 4 полей как предложение → пилот подтверждает/правит на сверке.

## Запрет правки задним числом

Вердикт сверки — **новая запись** со ссылкой на исходную (`Сверка H-NNN`), исходная запись не редактируется. Сохраняет историю обучения, не даёт переписать прошлое.

## Норма живых записей и входной фильтр

Журнал держит **8-15 живых записей** приоритета П1/П2 одновременно. Это рабочая ёмкость одной стратегической сессии — не архивный лимит: записи ниже П1/П2 или разобранные сверкой не считаются.

Переполнение (>15 живых П1/П2) — сигнал чистки, не повод расширять пакет решений следующей сессии. Разбор переполнения — пакетное решение пилота по трём корзинам: принять как гипотезу (пойдёт в обычный цикл сверки) / отклонить (не гипотеза по существу или неинтересно сверять) / оставить фоном (интересно, но не сейчас — снижается до П3-П4).

**Входной фильтр.** Новая гипотеза приоритета П1 принимается в журнал только со ставкой на текущий приоритет/результат периода (зеркало входного фильтра для рабочих продуктов — WP без привязки к приоритету периода не берётся в неделю). Без ставки — гипотеза допустима с приоритетом П2-П4, не П1.

## Ритуал еженедельной сверки

На Week Close (или по запросу «сверь гипотезы недели») — фильтр записей со статусом «на сверке» и наступившей датой:

1. Сверить критерий фальсификации с доступной фактурой (логи, коммиты, события, инфраструктура)
2. Предложить вердикт: подтверждена / опровергнута / частично подтверждена / неприменимо (если условие критерия не выполнено — напр. руководство не было доставлено, значит нельзя проверить гипотезу про его эффект)
3. Пилот утверждает или правит вердикт
4. Записать вердикт новой записью

## Каждое расхождение → действие

После вердикта — явный выбор: обновить уверенность на будущее / добавить шаг в чек-лист / завести РП / зафиксировать как кандидат в паттерн. Вердикт без выбранного действия = «повисший», не закрывает запись.

## Метрика калибровки

В недельном обзоре — две цифры: сколько гипотез сверено за неделю, какая доля high-confidence (≥80%) подтвердилась. Порог: из N записей с ~95% подтвердиться должно не менее 0.9N. Меньше → уверенность завышена, видно по цифре, не по ощущению.

## Событийная дисциплина (не только сверка)

Помимо вердикта сверки, журнал допускает ещё три типа добавляемых событий той же формы «новая запись со ссылкой на исходную, не правка задним числом»:

- **Исправление** — обнаружена ошибка в формулировке/критерии до наступления даты сверки (не вердикт, факт правки постановки).
- **Отзыв** — гипотеза больше не актуальна (предпосылка отпала, приоритет периода сменился) до наступления даты сверки.
- **Замена** — гипотеза переформулирована в новую, более точную запись; старая помечается статусом, ссылка на замену обязательна.

Все четыре типа события (вердикт, исправление, отзыв, замена) идут в одну и ту же историю — журнал остаётся полным аудитом мышления, не только полем итогов.

## Экстракция паттерна

Повторяющееся расхождение в одной предметной области — не личная ошибка, кандидат в Pack (доменное знание) или в этот регламент (LPF). Маршрутизация — через существующий Capture-to-Pack, не отдельный канал.
